# Licensing and third-party notices

zapper is MIT licensed (`LICENSE`, © 2026 Francis Lavoie). Its packages also contain other
people's code: the Rust crates the binary links and the npm packages bundled into the interface,
and on Windows libmpv itself. Their licenses require their notices to ship with the binary, so
every package carries them, regenerated by `just package` whenever what they're made from
changes, and **Settings > About > Open source licenses** shows them in the app.

zapper has no browser engine of its own (the system's WebKitGTK, WebView2 or WKWebView draws the
window), so there are no engine notices to carry.

## What ships, and where

| File | Contents |
| --- | --- |
| `LICENSE` | zapper's own license |
| `THIRD-PARTY-NOTICES-rust.txt` | Every crate zapper links, grouped by license, then where the LGPL crates' source is |
| `THIRD-PARTY-NOTICES-ui.txt` | Every npm package in the interface bundle, grouped by license, then any notices they ship |
| `MPV-FFMPEG-NOTICE.txt` | mpv and FFmpeg: their licenses, whether this platform's package contains them, where their source is (`packaging/licenses/`) |
| `GPL-3.0.txt` | Windows only: the GPL's text, for `libmpv-2.dll` (below) |
| `copyright` | `.deb` only: Debian's machine-readable copyright file (DEP-5), from `LICENSE` |

- The `.deb` installs them in `/usr/share/doc/zapper/`; the `.rpm` in
  `/usr/share/licenses/zapper/` (Fedora's place for them), without `copyright`. Both from the
  `files` maps in `src-tauri/tauri.conf.json`; `scripts/check-deb.sh` fails if one is missing
  or empty. Both packages also say `License: MIT` (`bundle.license`).
- The Arch package is the `.deb`'s payload, so the same files in `/usr/share/doc/zapper/`, with
  `/usr/share/licenses/zapper` (Arch's place for them) a link to that folder. Its `license`
  field lists MIT and every license the third-party notices' summaries name
  (`scripts/package-arch.sh`, which fails if a notice is missing or empty).
- The Windows installers put them in `licenses\` beside `zapper.exe`, as `.txt`
  (`packaging/windows/installers.conf.json`).
- On macOS they're in `zapper.app/Contents/Resources/licenses/` (`packaging/macos/dmg.conf.json`).
- In the app, the UI build copies them all into `dist/licenses/` with an `index.json` listing
  them, which the About pane reads (`src/components/Licenses.tsx`, a lazy chunk; the labels and
  order are `src/logic/licenses.ts`). Under `vite dev`, or a build made before the notices
  existed, the pane says they aren't in this build.

Each notices file lists every package under the license zapper uses it under (for "MIT OR
Apache-2.0", the one earliest in the allow-list, below) with the copyright lines from its license
files. The full text of each license follows its list once; texts that differ in more than their
copyright lines are printed separately, each with the packages that use it.

## How they're generated

`just licenses` generates everything; `just package` (and `package-windows`, `package-macos`)
run the same steps around their build, so the notices can't go stale.

1. **`scripts/licenses.sh`** writes `src-tauri/target/licenses/`: `cargo about generate`
   (cargo-about 0.9.2) produces JSON for zapper's graph on this platform
   (`x86_64-unknown-linux-gnu`; Windows' in Git for Windows' bash; this Mac's on macOS), without
   build-time, dev-only or harness crates, and `scripts/notices.py` turns it into
   `THIRD-PARTY-NOTICES-rust.txt`, and `LICENSE` into the `.deb`'s `copyright`. With
   `--if-changed` (what the package recipes pass) it does nothing when `Cargo.lock`,
   `Cargo.toml`, `about.toml`, `LICENSE` and the scripts are as they were for the last run (key
   in `src-tauri/target/licenses.key`); `ZAPPER_REBUILD=1` regenerates. Install cargo-about once:
   `cargo install cargo-about --version 0.9.2 --locked --features cli`. The release workflow
   installs it with `taiki-e/install-action`.
2. **The UI build** (`npm run build`, which `tauri build` runs) writes
   `dist/licenses/THIRD-PARTY-NOTICES-ui.txt` through the Vite plugin in `tools/licenses.mjs`. It
   works from the modules actually in the bundle, so devDependencies (Vite, TypeScript, the
   Tauri CLI) and tree-shaken code never appear and nothing bundled is missed; the bundler's own
   helpers (Vite's preload helper, Rolldown's runtime) are credited to their packages. It then
   copies in `LICENSE`, `packaging/licenses/MPV-FFMPEG-NOTICE.txt`, the Rust notices when they
   exist, and on a Windows build `packaging/licenses/GPL-3.0.txt`.

`src/__checks__/licenses.test.mjs` holds the pieces together: the allow-list has no copyleft
license, the build refuses a package outside it, every file the build can write has a label in
the About list, and every package (`.deb`, `.rpm`, Windows, macOS) carries the notices.

## The license allow-list

`accepted` in `about.toml` is the list of licenses zapper ships code under: MIT, Apache-2.0,
BSD-2-Clause, BSD-3-Clause, ISC, 0BSD, Zlib, MPL-2.0, EPL-2.0, Unicode, OFL-1.1, CC0-1.0,
BSL-1.0, Unlicense and CDLA-Permissive-2.0. The UI plugin reads the same list. A
crate or package under any other license, or with no recognisable license, fails the build with
its name, so a copyleft dependency is never added unnoticed. Review it, then drop the dependency
or record the decision: for a crate, in `about.toml` (for that crate alone, as below); for an npm
package whose `package.json` declares no license, in `tools/license-exceptions.json`.

- **MPL-2.0** (cssparser, selectors and others under Tauri's HTML handling; nucleo, the search) is
  file-level copyleft: it binds the covered files, not the MIT code beside them. They ship
  unmodified, their text is in the notices, and their source is on crates.io.

### The libmpv bindings: LGPL-2.1

`libmpv2` and `libmpv2-sys` (the Rust bindings to libmpv) are LGPL-2.1, accepted for those two
crates alone (`[libmpv2]` and `[libmpv2-sys]` in `about.toml`), never in general. They are
compiled into zapper's binary. The LGPL allows that as long as whoever gets the binary can relink
it with a modified copy of them, which zapper's published source (MIT) allows, and their source is
on crates.io: `THIRD-PARTY-NOTICES-rust.txt` ends with both addresses.

## mpv and FFmpeg

libmpv is a separate shared library, never part of zapper's binary. Whether a package contains
it depends on the platform; `packaging/licenses/MPV-FFMPEG-NOTICE.txt` says the same for users.

- **Linux:** not shipped. The `.deb`, `.rpm` and Arch package depend on the distribution's
  libmpv (`libmpv2 | libmpv1`, `libmpv.so.2`, `mpv`), which comes with its own copyright file
  and source package. Debian's and Fedora's are built with mpv's GPL parts, so libmpv there is
  GPL-2.0-or-later; nothing of it is in zapper's package.
- **Windows:** shipped. `libmpv-2.dll` is shinchiro/mpv-winbuild-cmake's `mpv-dev-x86_64` build
  (`tools/fetch-libmpv.ps1`, pinned to a release tag in `.github/workflows/release.yml`),
  installed beside `zapper.exe` (`src-tauri/tauri.windows.conf.json`). That build compiles mpv
  with its GPL parts (its default) and FFmpeg with `--enable-gpl --enable-version3`, statically
  linking x264, x265, libass, dav1d and many other libraries into the DLL. The DLL is
  therefore GPL-3.0-or-later as a whole. The installers ship the GPL's text (`GPL-3.0.txt`) and
  the notice. See "Open questions" for what the GPL also asks.
- **macOS:** not shipped; the port is unfinished and links whatever libmpv the Mac has.

## Open questions

Maintainer notes: decisions still pending before Windows builds are published.

- **The Windows DLL's source (GPLv3 §6).** Shipping a GPL binary means offering its
  Corresponding Source: mpv's, FFmpeg's and every statically linked library's, at the revisions
  built. mpv-winbuild-cmake's recipe names each library's repository but mostly tracks their
  latest commits, and its releases don't list the revisions they used, so pointing at the
  project is not a complete answer. Before Windows builds are published: host the source of the
  exact build beside each release (or build libmpv from pinned sources and host those), or give
  a written offer. An LGPL build of libmpv (mpv `-Dgpl=false`, FFmpeg without `--enable-gpl`)
  would shrink the problem but not remove it.
- **The DLL's bundled libraries' notices.** Several of the libraries inside it (dav1d, libvpx,
  libwebp, Opus, OpenSSL, among others) are BSD- or Apache-licensed and ask for their copyright
  notice to be reproduced; mpv-winbuild-cmake's archive doesn't carry them. A complete Windows
  package would collect them into a notices file of their own.

## Updating

- **New dependency, new license:** the build names it. Check its terms, then extend the
  allow-list or record an exception as above.
- **A new notice file:** add it to `noticeFiles()` in `tools/licenses.mjs`, give it a label in
  `src/logic/licenses.ts`, and map it in each package's config; `licenses.test.mjs` fails until
  all three agree.
